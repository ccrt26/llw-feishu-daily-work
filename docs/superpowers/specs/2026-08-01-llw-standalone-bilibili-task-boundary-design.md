# LLW Standalone Bilibili Task Boundary Fix

**Status:** 2026-08-01 implemented and accepted in production
**Production baseline:** V4.4.3
**Scope:** make `任务结束` and `当前任务已结束` close the active WeChat task so the next Bilibili link is processed as a new standalone task

## Goal

用户完成 PDF 或其他任务后发送精确文本 `任务结束` 或 `当前任务已结束`，系统必须先成功关闭后台 Task
Session，再回复任务已结束。随后发送一个受支持的 B 站链接和总结要求时，系统必须创建
全新任务，以 `source-001` 接收视频，并继续现有音频、画面、转写和 AI 总结链；“不保存”
时 Writer 必须为零。

## Confirmed root cause

当前控制词分类器接受 `结束`、`结束任务`、`结束当前任务`、`这个任务结束`，但遗漏
了用户实际使用的 `任务结束`。该文本因此进入普通 AI 对话；模型虽然回复“本次任务已
结束”，Task Session 仍保持 `active`。之后的 B 站来源被错误追加到旧任务的两个 PDF
来源之后，并在来源重新编号时触发现有索引编号缺陷，最终被宽泛错误误报为视频获取
失败。

## Selected design

1. 在唯一任务控制词分类边界中加入精确短语 `任务结束` 和真实验收中收到的
   `当前任务已结束`；保持无附件、整条消息精确
   匹配的现有限制，不做模糊意图推断。
2. 沿用现有 `end` 控制路径：取消正在运行的工作、调用 Task Session Manager 关闭
   当前任务、释放关闭任务的来源工作区，完成后才发送固定的“当前任务已结束。”回复。
3. 不修改 Bilibili 下载器、DNS 白名单、单次来源调用、媒体校验、ASR、画面时间线、AI、
   Writer 或公开视频域名。
4. 不实现“视频后追加 PDF”或“PDF 与视频联合分析”。本修复只保证结束旧任务后，
   下一个 B 站视频是新的独立任务。
5. 部署后处理当前残留状态：通过现有受控关闭语义关闭当前活动任务并释放其任务来源
   工作区，不直接手工编辑状态 JSON。用户资料和已归档文件不删除。

## Alternatives rejected

- **所有 B 站链接强制新建任务：**会破坏未来明确说“结合刚才资料”时的连续任务语义。
- **仅要求用户改说 `结束任务`：**保留“回复已结束但后台未结束”的产品缺陷。
- **修复多来源视频重新编号：**能让 PDF 后追加视频继续运行，但超出本次确认范围，且
  不能修复虚假的任务结束回执。

## Error handling

- 没有活动任务时发送 `任务结束`，继续返回现有“当前没有进行中的任务”语义。
- 关闭失败时不得回复已结束；沿用现有失败 Outcome 和零写入规则。
- 新 B 站任务若在来源、ASR、画面、AI 或 Writer 阶段失败，继续使用各自现有错误边界；
  本修复不掩盖或改写这些错误。

## Verification

严格按 RED → GREEN：

1. 单元测试先证明 `任务结束` 和 `当前任务已结束` 返回 `null`，再要求它们分类为
   `{kind:"end"}`；附件携带同一句时仍不得作为控制指令。
2. Dispatcher/Task Session 测试证明：活动任务收到这两句任一句后状态真正关闭，固定
   回复只发送一次，旧任务来源工作区被释放。
3. 增加一条微信纵向测试：已有 PDF 任务 → `当前任务已结束` → 新 B 站链接“总结内容 不保存”
   → 新 taskId、视频为 `source-001` → 视频 Reader、AI 各调用一次 → Writer 0 →
   Outcome 正常回复。
4. 运行任务控制、Dispatcher、任务来源、Bilibili 来源准备和相关微信纵向聚焦测试。
5. 候选通过后运行一次完整本地回归，建立可回退部署点，再更新生产并完成服务、状态和
   自然微信入口健康检查。

## Acceptance criteria

- `任务结束` 和 `当前任务已结束` 的回复与后台状态一致，不再出现“嘴上结束、后台仍活动”。
- 下一条独立 B 站视频创建新任务，并以 `source-001` 进入现有视频链。
- 不保存请求调用 Writer 0 次，不改变 PDF、抖音、网络权限或多来源能力。
- 当前残留活动任务通过正式关闭路径清理，不手工改状态文件，不删除用户资料。
